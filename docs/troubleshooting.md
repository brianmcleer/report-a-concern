# Troubleshooting

Symptom first. Find the row that matches what you see, confirm the cause with the check in the third column, apply the fix. Placeholders are the same as in [deployment.md](deployment.md). Where a fix says "restart the proxy", the commands are in [operations.md](operations.md#restarting-the-proxy).

Two tools answer most questions before you open this table. `Notification_Log` says whether an email was attempted and what happened. Task Scheduler history says whether a script ran and how it exited. Check both first.

## Public submissions and the proxy

| Symptom | Likely cause | Confirm | Fix |
|---|---|---|---|
| `/ReportAConcern/proxy/health` returns an IIS HTML error page with status 500 instead of JSON | The rewrite rule fired but nothing is listening on port 5000. The Flask process is not running. | `netstat -ano \| findstr :5000` on the server shows nothing. Task Scheduler shows the proxy task ended with a non-zero result. | Run `<clone-python> rac_proxy.py` in a console to see the import or config error (a missing `proxy_config.py` exits immediately with a message). Fix it, then start the scheduled task. |
| `/ReportAConcern/proxy/*` returns 404 while the app itself loads | Application Request Routing is not installed or its proxy setting is off, or the site-level rewrite rule is missing. ARR missing gives 404, not 502. | IIS Manager, server node, Application Request Routing Cache, Server Proxy Settings: is Enable proxy ticked? Default Web Site, URL Rewrite: is the RAC Flask Proxy rule present? | Install ARR 3.0 and URL Rewrite 2.1, enable the proxy, recreate the rule at site level from `proxy/web.config.example`. |
| Submissions stopped working immediately after a widget republish | The rewrite rule (or a header) had been placed on the `ReportAConcern` application instead of the site, and publishing wiped the application folder. | `curl -I .../proxy/health` returns 404; the application's URL Rewrite feature is empty. | Recreate the rule at Default Web Site level; delete any app-level copy. Restore from an `appcmd` backup if you have one. |
| Browser console shows "Load failed", "TypeError: Failed to fetch" or a CORS error and the POST never appears in the proxy log | A widget URL (proxy base, feature layer, comments table) is on a different origin than the page: different host, alias versus real name, or `http` versus `https`. The browser blocks the request before it leaves. | DevTools, Network tab: the failing request's host differs from the page's host, or the preflight `OPTIONS` has no `Access-Control-Allow-Origin`. | Make every widget URL same-origin with the page, and put that exact origin in `CORS_ORIGINS` in `proxy_config.py`. Restart the proxy. |
| Submissions return 403 Forbidden | The request reached the FeatureServer directly and the site-level "Block Direct FeatureServer POST" rule refused it. The widget is posting to the FeatureServer instead of the proxy. | DevTools shows the POST URL under `/arcgis/rest/services/.../FeatureServer/`. | Set the widget's write endpoint to `https://gis.example.gov/ReportAConcern/proxy`. The block rule is doing its job; do not remove it. |
| Submissions return 429 | Rate limit exceeded for that client IP. | `Notification_Log` has a `BLOCKED` row with the rate-limit reason and the source IP. | Legitimate shared-NAT traffic: raise `RATE_LIMIT_MAX` in `proxy_config.py` and restart. Abuse: leave it. |
| Submissions return 400 with a validation message | The proxy's payload check refused it: more than one feature, geometry outside `BBOX_*`, category not in `VALID_CATEGORIES`, missing or over-long description. | The `BLOCKED` row in `Notification_Log` names the check. | If the check is wrong for your area (bounding box too tight, new category not added), update `proxy_config.py` and restart. |
| Submissions return 500 and the proxy log shows a traceback | Malformed JSON from the widget, an SDE or FeatureServer failure, an expired service account password, or the attribute rule rejected the insert. | `C:\Apps\RAC\logs\rac_proxy.log` has the traceback. An Arcade error code 1001 in the response means a constraint rule fired. | Rule rejection is expected for out-of-area points; make sure the widget shows the redirect message. For SDE errors, check the account password and that the geodatabase is accepting connections (`arcpy.AcceptConnections(sde, True)` if a schema script died). |
| Widget map fails to load for anonymous users with "Item does not exist or is inaccessible" | One of the Portal items the app loads is not shared with Everyone. It is often not the feature service but the basemap, a locator, or the display service. | Sign out of Portal and open the app in a private window. Open each item the app references in Portal and check Share. | Share every item the public app uses with Everyone. |
| `applyEdits` returns HTTP 499 "Token Required" even though the item is public | The Portal item is shared, but the federated ArcGIS Server service still requires a token. Item sharing and service security are separate settings. | Open the service URL without a token: it prompts or returns 499. | Server Manager, the Reporter service, Security: allow anonymous access. |
| Photo upload returns 415 | The magic-byte check rejected the file; the content is not JPEG, PNG, WebP or HEIC despite the extension. | `BLOCKED` row names the detected type. | Nothing to fix server-side. Ask the citizen for a standard image. |
| Photo upload returns 413 | The file exceeds `MAX_ATTACHMENT_BYTES`, or IIS Request Filtering's maximum content length is lower than the proxy allows, or the service `maxUploadFileSize` was reset by a republish. | Compare the three limits. Admin REST shows `maxUploadFileSize`. | Run `patch_rac_upload_restrictions.py`; raise the IIS limit at the site level if it is the smaller one. |
| Photo upload returns 500 | Write to `Tickets__ATTACH` failed. | Proxy log traceback names the SDE error. | Usually disk or permissions on SQL Server; check free space. |
| Status page `?ticket_number=N` shows nothing | The ticket number does not exist (citizen mistyped), or the widget's status query and comments table URLs were reset in Builder, or a CORS or 403 error on the read. | Query `Tickets` for the number. Browser console for errors. | Correct the URLs in the Experience Builder app config and republish. |
| Geocoder returns no suggestions | The configured locator URL is wrong or the locator service is down; the World Geocoder fallback needs internet access from the browser. | Open `geocoderUrl?f=json` in a browser. | Fix the URL or restart the GeocodeServer service. Rebuild the locator if addresses are stale. |
| Submissions take more than 3 seconds | Cold Reporter service, fragmented spatial indexes, missing composite indexes on the routing tables, or stale statistics slowing the Arcade `FeatureSet` filters. | Time `curl` on `/proxy/health` (IIS or ARR), then a direct `applyEdits` on the internal endpoint (proxy versus service), then a raw SQL INSERT (service versus rules). Check `sys.dm_db_index_physical_stats`. | Rebuild indexes above 30 percent fragmentation, `UPDATE STATISTICS ... WITH FULLSCAN` on the four routing tables, set `MinInstancesPerNode` above 0 on the Reporter service. |

## Scripts and Task Scheduler

| Symptom | Likely cause | Confirm | Fix |
|---|---|---|---|
| A task shows Last Run Result `0x800700C1` ("not a valid Win32 application") on Windows Server 2025 | The task action points at the base `arcgispro-py3` `python.exe` under Program Files, which the scheduler cannot launch under the service account on this OS build, or at a `python.exe` that does not exist on this server. | Open the task's Actions tab and copy the path; run it from a console as the service account. | Point the task at the cloned environment's `python.exe` (`<clone-python>`). The clone lives under a normal user-writable path and launches correctly. For scripts that need `arcpy`, clone with `conda create --clone arcgispro-py3` so the clone carries `arcpy` too. |
| Task shows result `0x1` | The script raised and exited 1. | The script's log in `C:\Apps\RAC\logs`, and the failure alert email if `ALERT_RECIPIENTS` is set. | Fix the cause named in the log. |
| Task shows `0x41306` | Someone ended the task manually. | Task Scheduler history. | Run it again. |
| Task ran with result `0x0` but nothing was sent and no log rows appeared | The scheduler discards stdout and stderr, so an early error can be invisible; or the script read no pending rows because of the versioned-view lag described below. | The script's own log file. `SELECT COUNT(*) FROM Tickets WHERE notification_sent = 0` shows pending rows. | Run the script by hand from a conda prompt as the service account to see the output. |
| Citizen did not receive the confirmation | Several possibilities, in order of likelihood. | `Notification_Log` for that `ticket_id` and the notifier script. | `SUCCESS` row: the mail left the server; check their spam folder. `FAILED` row: read `error_msg` (relay rejection or a typo in the address). No row and `notification_sent = 0`: the task did not run; check history. No row and `notification_sent = 1`: the script was killed between marking and sending; set the flag back to 0 only if the routing email also did not go out, otherwise resend by hand. |
| Emails to outside domains fail with `451 4.4.4`, `451 4.4.62` or `550 5.7.64` while internal recipients succeed | The SMTP host is an inbound mail exchanger, not an outbound relay, and refuses unauthenticated mail to external domains. The server's outbound IP needs an outbound connector (Exchange Online) and an SPF entry. | The error text in `Notification_Log`; a `telnet smtp.example.gov 25` plus `EHLO` succeeds, and a test send to an internal address works. | Mail administrator adds the server's static outbound IP to the connector and SPF record. No script change. A host move is also a connector and SPF change. |
| Duplicate confirmation, reassignment or survey emails | A script is sending inside a batch edit session and committing the sent flag at the end, so one commit failure (typically a version conflict with a ticket open in the Manager) rolls back every flag after every email was delivered. Or two servers are running the scheduled tasks against the same database. | `Notification_Log` shows repeated `SUCCESS` rows for the same ticket and subject five or thirty minutes apart. Check that only one server has the RAC tasks enabled. | The shipped scripts commit one ticket per operation (mark-first for the notifier, send-then-mark for the rest); if you have modified them, restore that ordering. See [operations.md](operations.md#why-the-flag-is-committed-before-the-email-is-sent). Never run the tasks on two servers at once. |
| The same public comment is emailed every 30 minutes | The mailer reads pending comments through one layer (versioned view) and writes `email_sent` through the other (base table or an edit session). On a table whose archive is broken, the two disagree and the flag write is never seen by the next read. | `Ticket_Comments.email_sent` is 1 in the base table but the versioned view still shows NULL, or the reverse. | Keep the read and the write on the same layer. The shipped comments mailer does both by direct SQL on the base table. Repair the archive state per operations.md. |
| Survey emails go out hours or days late, or only after the monthly compress | The survey mailer reads `Tickets` through the versioned view, and the Manager's Resolved edit is sitting in the delta tables in a state the view does not yet expose, most often after a long gap since the last Compress or when the Manager's edits are in a named version that has not been posted. | Query the base table and the `_evw` view for the ticket: status differs. `SDE.sde_state` has many rows. | Run a Compress (operations.md). Confirm the Manager service edits the DEFAULT version. Schedule compress monthly so the lag never builds. |
| Reassignment notice did not fire | `assigned_to` equals `last_notified_assignee`, so there was nothing to detect: the Manager never saved the change, or the script already ran. Or the script ran and failed to send. | Compare the two fields. Look for the ASSIGN comment. `Notification_Log` for a `FAILED` row. | If the fields differ and no row exists, the task is not running: check its history. If a `FAILED` row exists, read the error. |
| Reassignment email shows category as a number | The script is decoding subtypes with `arcpy.Describe().subtypes`, which is not a valid property, so decoding silently fails. | The email body. | Use `arcpy.da.ListSubtypes` (the shipped script does). |
| Survey email not sending | Ticket is not Resolved or Closed, or `survey_sent` is already 1, or the task action still carries `--dry-run`, or the Survey123 item ID changed. | Query the ticket. Open the task's Actions tab. | Remove `--dry-run`; update `SURVEY_BASE_URL` and `SURVEY_ITEM_ID` in `config.py` if the form was recreated. |
| Survey responses are not imported | ArcGIS Online credentials wrong (`rac_secrets.py`), the form's field names changed, or the ticket link parameter is arriving as the literal `${ticket_id}` placeholder. | Script log. Query the survey layer in ArcGIS Online. | Fix credentials; restore field names in the form (renaming a field breaks the pull); the placeholder rows are skipped by design. |
| Staff follow-up email went to the wrong person | The follow-up targets the ticket's last editor, and someone edited the ticket after it was closed. | `last_edited_user` on the ticket. | Expected behavior. If it becomes common, add a stamped `resolved_by` field and change the lookup. |
| Directors report is missing tickets | The director is not in `DIRECTOR_DICT` for that category, or the tickets are younger than the age thresholds (24 hours Open, 7 days Received, 30 days In Progress). | `config.py`; ticket ages. | Edit `DIRECTOR_DICT` or the `THRESHOLD_*` values. |
| Script fails importing `datetime`, `zoneinfo` or `arcpy` with a strange attribute error | A stray `datetime.py` (or another standard-library name) on `sys.path`, often from an IDE content root, is shadowing the real module. | `python -c "import datetime; print(datetime.__file__)"` points at a file in your project. | Rename the file. `rac_common.py` repairs `sys.modules['datetime']` before importing dependents, but only for that name. |
| Direct SQL insert into `Notification_Log` fails with a NOT NULL violation on `OBJECTID` | Direct SQL bypasses the geodatabase's ObjectID allocation. | The error text. | Supply `OBJECTID = MAX(OBJECTID) + 1` with a retry on collision; use `rac_common.notif_insert()`. |
| `ArcSDESQLExecute` raises "ArcSDE Error -65" on a SELECT | A `uniqueidentifier` or long-text column in the result set; the binding cannot handle those types. | The SELECT list. | `CAST` GUIDs to `varchar(50)` and `nvarchar(max)` columns to a bounded `varchar`. |
| An `arcpy` cursor update "succeeded" but the row did not change | Writes to a versioned table outside an `arcpy.da.Editor` session are silently discarded. | No error, no change. | Wrap the cursor in an edit session, or use direct SQL on the base table. |
| Compress fails with "Cannot insert duplicate key" on `R19_SDE_ROWID_UK` and "Unable to trim state" | A versioned insert into `Ticket_Routing` reused an OBJECTID that already exists in the base table, because earlier direct-SQL loads did not advance the row-id counter. | The error names the table and state. | Unregister `Ticket_Routing` as versioned with `NO_KEEP_EDIT`, register it again, re-add the row by direct SQL at `MAX(OBJECTID) + 1`, Compress. Add rows to that table by direct SQL from then on. |
| Nobody can connect to the geodatabase | A schema script died before its `finally` block and left `AcceptConnections(False)` in effect. | `arcpy.ListUsers` from an administrative connection works; everything else is refused. | `arcpy.AcceptConnections(sde, True)`. |

## Manager, staff apps and Portal

| Symptom | Likely cause | Confirm | Fix |
|---|---|---|---|
| Manager will not save edits | Expired Portal token, missing edit permission on the Manager service, or an SDE error. | DevTools, the `applyEdits` response body. | Sign in again; grant the group edit access; read the SDE error. |
| Saves succeed but no ASSIGN comment is written | The published Manager app is a stale build. | Compare the version banner in the widget with the repository tag. | Rebuild and republish. |
| Map highlight does nothing after a zoom | The layer view was not loaded when `select()` fired, or the `definitionExpression` was cleared by the `goTo` animation. | Browser console. | The shipped widget reapplies the expression in a `finally` after `goTo`; confirm the deployed build includes it. |
| Dashboard or helper page hangs at "Authenticating with Portal" or shows Invalid Token | The OAuth callback URL does not exactly match the redirect URI registered on the Portal app, a popup blocker is interfering, or `registerServers` uses an alias instead of the server's real host name. | Console log shows the registered callback URL; compare with the Portal app's Redirect URIs. | Match the URIs exactly; allow popups; use the real server host name for `serverRoot`. |
| A page you just deployed still shows the old version | Browser cache. The site-level outbound rule sets no-cache on `.js` and `.json`, but HTML and CSS are still cached. | Hard-reload with Ctrl-F5 shows the new version. | Nothing to fix; tell users to hard-reload after a deploy. |

## Migration and environment lessons

| Symptom | Likely cause | Confirm | Fix |
|---|---|---|---|
| The alias works from outside but tests from the office hit the old (or wrong) server, or the reverse | Split DNS. The internal DNS zone has its own record for the alias and was not updated with the external one, so `gis.example.gov` resolves to different addresses inside and outside the network. | `nslookup gis.example.gov` from a workstation on the network and from a phone on mobile data return different addresses. | Update both zones. During a cutover, confirm both before enabling jobs on the new server. Keep the alias TTL low for the week around the change. |
| `pip install` into `arcgispro-py3` fails with "Access is denied" even when elevated | The base ArcGIS Pro environment is read-only on current installs. | The error. | Clone the environment (`conda create --clone arcgispro-py3 --name arcgispro-py3-rac`) and install into the clone; point the proxy task at the clone's `python.exe`. |
| Proxy task fails at boot with "No module named flask" | The task action points at the base interpreter, which has no Flask or waitress; those were installed into the clone. | The task's Actions tab. | Change the action to `<clone-python>`. Imported task XML from another server carries the old path. |
| Remote `curl` to port 5000 times out while `localhost` works | Windows Firewall blocks 5000 from other machines. | Expected. | Nothing. IIS talks to the proxy over loopback; the port must stay closed to remote addresses. |
| After moving servers, emails to citizens bounce but internal mail works | The new server's outbound IP is not on the mail connector or SPF record. | The `451`/`550` codes above. | Mail administrator adds the new IP. This is the gating item for any host move; request it two weeks ahead. |
| After moving servers, the widget's network tab shows requests to the old host | A hard-coded host name in the widget config, the templates, `config.py` or `proxy_config.py`. | `findstr /S /I "oldhost" C:\Apps\RAC\*.py C:\Apps\RAC\*.html C:\inetpub\wwwroot\ReportAConcern\*.json` | Replace with the alias for citizen-facing URLs and the new real name for server-internal ones. |
| Both servers are emailing citizens | The scheduled tasks are enabled on the old and the new server at the same time against the shared database. | `Notification_Log` rows written from two hosts. | Disable every RAC task on one server immediately. Only one server may poll the flags. |
| `git` commands fail with "index.lock exists", "unable to write" or files reverting on their own | The repository is inside a OneDrive (or other sync client) folder. The sync client locks and re-syncs files in `.git` while git is writing. | The checkout path is under a synced folder. | Move the checkout to a local, unsynced path (for example `C:\Apps\RAC`) and never clone into Documents or Desktop when those are redirected to OneDrive. |
| Locator rebuild produces inconsistent references in published services | `LOCATOR_BASE_PATH` is a local drive path rather than the UNC path the server registered. | The script's constant. | Set it to the registered UNC path and rebuild. |

## Disaster recovery in brief

| Event | Response |
|---|---|
| Public server unreachable | Confirm with IT it is the server, not DNS. Fail over the alias to a standby if one exists; otherwise announce the outage. After recovery, verify tasks enabled, proxy listening, IIS rules present, certificate valid, then run the post-deploy checks. |
| Database corruption | Restore from the SQL backup chain. Run `AnalyzeDatasets` and `RebuildIndexes`. Open Tickets in Pro and confirm the five attribute rules are attached; recreate them from your saved Arcade if not. Confirm the lookup tables are populated. Submit a test ticket. Use `Notification_Log` to identify tickets emailed but no longer present. |
| Lost attachments only | Restore `Tickets__ATTACH` from backup. The relationship is auto-managed. Tickets submitted after the backup show without photos; ask citizens to resend via comment. |
| Rows deleted by mistake | Check the `_H` archive table for the deleted rows and `INSERT ... SELECT` them back; if archiving on that table is broken, restore from backup. If a wipe ran against production, stop everything and coordinate the restore rather than repairing under pressure. |
